# CURRENT_TASK.md — Текущая задача

## Шаг 1.3 — Хватание кубика руками (через `@c-frame/physx`)

> ⚠️ Шаг 1.3 был **переопределён** в начале Сессии 5. Прежний план на `super-hands` отменён. Текущий план — захват через встроенные компоненты `@c-frame/physx`. Полный контекст разворота — в `PROJECT_LOG.md`, раздел «Разворот с Cannon на PhysX».

---

## 🎯 Цель шага (одним предложением)

Игрок в Quest 3 может поднести руку к кубику, нажать триггер на контроллере — кубик прилипает к руке. Отпустил триггер — кубик падает по физике (PhysX), с корректным импульсом от движения руки.

---

## ✅ Критерий завершения

Надеваю Quest 3 (через Quest Link, на `http://localhost:<порт>`), открываю проект, подхожу к кубику, беру его рукой через триггер, переношу в другое место, отпускаю — кубик падает на пол по физике PhysX. Если резко махнуть рукой и отпустить триггер — кубик улетает с импульсом, не «падает на месте».

Шаг закрыт, когда это работает в реальном Quest 3 через Quest Link. Деплой на Netlify для закрытия шага не требуется.

## 🗂 Рабочий контекст (Working Context)

### ИЗВЕСТНО (факты, проверенные)

- Этап 0 закрыт: сцена A-Frame 1.5.0 с белой комнатой 3×3×3 м и пьедесталом (цилиндр R=0.3 м, H=1 м) в центре работает локально, на Netlify и в Quest 3.
- Шаг 1.1 закрыт (Cannon-версия): пол и пьедестал имеют `static-body`, тестовый красный кубик 10×10×10 см с `dynamic-body="mass: 1"` падает на пьедестал. **Будет переделано на PhysX в шагах F–G.**
- Шаг 1.2 закрыт: оба entity рук — внутри rig'а игрока `<a-entity id="player">`, на каждом стоит `hand-controls` + `gltf-model` с локальной GLB-моделью из `assets/models/`. В Quest 3 руки видны и трекаются.
- Стек физики и захвата выбран — `@c-frame/physx` (см. `PROJECT_LOG.md`, «Разворот с Cannon на PhysX»).
- Захват в PhysX реализуется встроенными компонентами `physx-grabbable` (на захватываемые объекты) + `hand-grab` (на entity руки). Отдельная библиотека уровня `super-hands` не нужна.
- В Сессии 4 `super-hands` не удалось зарегистрировать в `AFRAME.components`. Это причина разворота, не повод возвращаться.
- CDN — **только jsDelivr**. Без VPN, без `aframe.io`, без `unpkg.com`.
- Стратегия тестирования — локально через `npx serve` + Quest Link. Netlify — только в конце этапа или по запросу пользователя.

### НЕИЗВЕСТНО (надо выяснить до кода)

- **Точная актуальная версия `@c-frame/physx`** на момент Сессии 5. Проверяется в шаге A через GitHub-репозиторий `c-frame/physx`.
- **Точная CDN-ссылка** на бандл (`physx.min.js` или аналог) через jsDelivr — `cdn.jsdelivr.net/npm/@c-frame/physx@<версия>/...`. Проверяется в шаге A.
- **Откуда PhysX тянет `.wasm`-файл** при инициализации. Если со стороннего CDN, недоступного из РФ — нужно положить локально в `assets/` и указать путь через параметр системы. Проверяется в шаге B при первом запуске.
- **Точное имя системного атрибута** на `<a-scene>` для PhysX (`physx="..."`?) и список его параметров. Не выдумывать — взять из README PhysX.
- **Точные имена и параметры** компонентов `physx-body`, `physx-grabbable`, `hand-grab` — взять из README PhysX, не из памяти.
- **Нужны ли дополнительные компоненты на руках** для обработки триггера контроллера (`oculus-touch-controls`, `meta-touch-controls`) — или `hand-grab` обрабатывает это сам. Проверяется в шагах B и H.
- **Совместимость `hand-controls` + `physx-body="type: kinematic"`** на одном entity. Если конфликт — возможно, потребуется разделить визуализацию руки (`hand-controls` + GLB) и физическое тело руки на отдельные entity.

### ПРЕДПОЛОЖЕНИЯ (гипотезы, не подтверждённые)

- **Совместимость `hand-controls` + физика руки.** Если возникнет конфликт (руки перестанут трекаться, или физика руки будет дёргаться) — не пытаться чинить наугад. Зафиксировать симптом, обсудить, возможно разделить визуал и физику на разные entity.

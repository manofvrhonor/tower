## Цель

Добавить в сцену кубики со свойством `float` (невесомость + инерция). Кубики:
- парят в комнате без гравитации;
- физически сталкиваются со стенами, полом, потолком, друг с другом, с руками;
- отлетают в сторону при ударе рукой без триггера;
- ловятся рукой при зажатом триггере через существующий `physx-grab`.

**Купол, переключение `float ↔ gravity` и collision filtering — НЕ в этой задаче.** Это задача 3, сделаем после задачи 2.

---

## Критерий завершения

✅ В сцене есть минимум один кубик со свойством `float`.
✅ Кубик не падает на пол — висит/дрейфует в воздухе.
✅ Кубик отскакивает от стен и пола (если долетел).
✅ При ударе рукой без триггера — кубик отлетает.
✅ При зажатии триггера рядом с кубиком — кубик хватается рукой.
✅ При отпускании триггера — кубик отпускается, продолжает движение по инерции.
✅ В консоли нет красных ошибок.
✅ В Quest 3 поведение визуально корректно.

## Working Context

### ИЗВЕСТНО

- A-Frame 1.7.1 + `@c-frame/physx@v0.3.0` через jsDelivr.
- `physx-grab` уже на руках, ловит синий кубик так же, как красный референсный — отдельный код для захвата плавающих не нужен.
- В `@c-frame/physx@v0.3.0` PhysX-API доступно через `sceneEl.systems.physx.PhysX` (НЕ через глобальный `PhysX` или `window.PhysX`).
- В `sceneEl.systems.physx.PhysX` **нет класса `PxVec3`**. Есть `PxVec3Vector` — это контейнер-массив векторов, не сам тип. Метод `rigidBody.setLinearVelocity` принимает обычный объект `{x, y, z}` (проверено диагностическим перебором четырёх способов в Сессии 6: PxVec3 из system / plain object / THREE.Vector3 / отдельные аргументы — сработал второй).
- Энумы PhysX (`PxActorFlag`, `PxShapeFlag`, и т.д.) — это **объекты-обёртки с полем `.value`**, а не числа. В методы вроде `setActorFlag` нужно передавать **сам объект-обёртку**, не число. Передача числа молча игнорируется.
- Готовность `rigidBody` надёжнее всего ловить **поллингом** (`setInterval` каждые 100 мс), события `body-loaded` / `physx-body-loaded` в этой версии не приходят стабильно.
- Тестовый красный кубик (Этап 1, dynamic + гравитация) хватается и отскакивает — референс «обычного dynamic».
- Все геймплейные числа — в `js/config.js`.

### НЕИЗВЕСТНО

- Точные значения `linearDamping` / `angularDamping` для приятного парения. Сейчас 0.1/0.1, подбираются на Шаге 5.
- Точное значение `restitution` для приятных отскоков. Стартуем с 0.9 на Шаге 5, подбираем итеративно.
- Поведение при множественных столкновениях кубиков друг с другом — увидим на Шаге 6.

### ПРЕДПОЛОЖЕНИЯ

### ПРЕДПОЛОЖЕНИЯ

- На Шаге 5 атрибут `physx-material` будет применён к entity до того, как `physx-body` создаст shape — стандартное поведение @c-frame/physx. Если нет — добавим setter материала через систему после готовности тела.

### РЕШЕНО

- Кубики **dynamic, не kinematic**. (Сессия 6)
- Парение = физика без гравитации + низкий damping + стартовый импульс. (Сессия 6)
- `state = 'float'` хранится в компоненте. Переключение float ↔ gravity — в задаче 3, не сейчас. (Сессия 6)
- Тестовый красный кубик из Этапа 1 остаётся в сцене как референс. (Сессия 6)
- Цвет — `#4A90E2`, размер — 0.1 м, точка спавна на Шаге 3 — (0, 1.7, 0). (Сессия 6)
- API отключения гравитации: `rb.setActorFlag(sys.PhysX.PxActorFlag.eDISABLE_GRAVITY, true)`. Передавать **объект-обёртку**, не число. (Сессия 6)
- API стартового импульса: `rb.setLinearVelocity({x, y, z}, true)`. Plain JS-объект, без оборачивания в PxVec3. (Сессия 6)
- Готовность тела — поллингом `rigidBody`, не событием. (Сессия 6)
- **«Гонка инициализации» (кубик чуть проседает в первые 100–200 мс) — не чиним в рамках 2.** Решение откладывается до Этапа 4 (механизм замедления времени) или до централизованного спавнера, где проблема решится единообразно. На геймплей синего кубика после старта это не влияет. (Сессия 6)

## Подводные камни

⚠️ **PhysX-WASM enum'ы — это объекты-обёртки.** Передача голого числа в `setActorFlag` и аналоги тихо игнорируется. Всегда брать через `sceneEl.systems.physx.PhysX.<EnumName>.<member>`.

⚠️ **Глобального `PhysX` / `window.PhysX` нет.** Только через систему сцены.

⚠️ **«Гонка инициализации»** — между моментом создания entity и моментом, когда `rigidBody` доступен, проходит 100–200 мс. За это время дефолтная гравитация PhysX чуть сдвигает тело. Сейчас принято: жить с этим до Этапа 4. Если в будущем понадобится pixel-perfect старт — варианты: создавать как `static`/`kinematic` и переключать на `dynamic` после готовности, либо принудительно ставить позу через `rb.setGlobalPose(...)` (требует разобраться с конструктором `PxTransform` в этом биндинге).

⚠️ **Damping = 0 = бесконечный разгон.** Минимум 0.05.

⚠️ **`restitution` дефолтного PhysX-материала ≈ 0.** Любое тело без явно заданного `physx-material` гасит удары почти полностью и быстро останавливается. Для «вечного» дрейфа кубикам нужен собственный материал с высокой restitution (планируется на Шаге 5).

⚠️ **Туннелирование** при сильном импульсе. Стартовая скорость 0.2 м/с — безопасно.

⚠️ **Шаг 5 (damping) — итеративный.**

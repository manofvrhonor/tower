## 🎯 ГЛАВНАЯ ЦЕЛЬ

VR-игра **Tower of Time** для Meta Quest 3 в браузере (WebXR), по постоянной ссылке.

### Геймплей

Игрок в белой комнате 3×3×3 м. В центре — стол-пьедестал с прозрачным куполом. Вокруг в невесомости плавают:
- **цветные кубики** — для сборки башни по схеме на столе;
- **серые мусорные кубики** — визуальный шум (`isTarget: false`);
- **красные светящиеся шары с трейлами** — летают по траекториям, опасны.

### Купол

- Плавающие кубики отскакивают от купола снаружи.
- Рука с кубиком свободно проходит сквозь.
- Отпустил кубик внутри → становится физическим, падает на стол.
- Отпустил снаружи → летит в невесомости с импульсом руки.
- Скатился со стола, коснулся пола → возвращается в плавающий режим.
- Красные шары проходят сквозь купол, могут сбить башню.

### Замедление времени (как в игре SUPERHOT)

- Игрок замер → `timeScale ≈ 0.05`.
- Двигается → `timeScale = 1.0`.
- Применяется к скриптовому движению (плавающие кубики, шары).
- Физика рук, физика на столе, сам игрок — реальное время.

### Отбивание

В комнате — бита/сковородка/ракетка/рыба, ими отбиваются красные шары.

### Победа / поражение

- **Победа:** башня собрана по схеме, неподвижна несколько секунд.
- **Поражение:** красный шар коснулся капсулы тела игрока.

### MVP

Друг надевает шлем без объяснений, проходит за 2–5 минут, говорит «прикольно».

### Таймлайн

~1 неделя.

### Не-цели

Уровни, меню, сохранения, графика AAA, мультиплеер, не-VR версии.

### Компоненты

- **`@c-frame/physx@v0.3.0`** — единый физический движок NVIDIA PhysX через WebAssembly.
  - Бандл: `https://cdn.jsdelivr.net/gh/c-frame/physx@v0.3.0/dist/physx.min.js`
  - WASM: `https://cdn.jsdelivr.net/gh/c-frame/physx@v0.3.0/wasm/physx.release.wasm` (явно через параметр `wasmUrl`).
  - Используем компоненты: `physx` (на `<a-scene>`), `physx-body="type: static|dynamic|kinematic"`, `physx-joint`, `physx-material`.
  - Параметр `useDefaultScene: false` — пол и стены делаем свои, как `physx-body="type: static"`.
- **`physx-grab`** — локальный компонент `js/components/physx-grab.js`. Скопирован один-в-один из `examples/components/grab.js` репозитория `c-frame/physx@v0.3.0`. Захват реализован через `physx-joint type: Fixed` между рукой и схваченным телом — dynamic-тело остаётся dynamic, что позволяет реалистично ставить кубики друг на друга.
- **`hand-controls`** (встроенный в A-Frame) — отображение и трекинг рук. На каждой руке — `gltf-model` с локальной GLB из `assets/models/`. Внутри руки — дочерний `<a-sphere visible="false" physx-body="type: kinematic; emitCollisionEvents: true" radius="0.05">` как физический коллайдер.
- **aframe-extras** — пока не используется, по необходимости.

## 🏗 АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### CDN — только jsDelivr

Все внешние библиотеки — через `https://cdn.jsdelivr.net/`.
Не использовать: `aframe.io`, `unpkg.com`, `cdn.aframe.io`, любые другие CDN.
Причина: стабильность из РФ без VPN, единая точка отказа.

### Стратегия тестирования — локально, не Netlify

- Цикл разработки: правка → сохранить → `npx serve` → перезагрузить вкладку Chrome → при необходимости войти в VR через Quest Link.
- **Quest Link + localhost.** Quest 3 подключён к ПК через Quest Link. В десктопном Chrome на `http://localhost:<порт>` иммерсивный VR работает напрямую — шлем показывает то, что в браузере.
- Деплой Netlify — только в конце этапа или по явному запросу пользователя.
- Публичная HTTPS-ссылка нужна, только если тестируем в Quest Browser напрямую (без Quest Link). Тогда — деплой по запросу.

### Git и откаты

- Каждый микро-шаг = отдельный коммит в `main`.
- Откаты — через `git reset` / `git checkout`, не через Netlify rollback.
- `git push` — пакетом в конце сессии или для бэкапа, не после каждого коммита.

### Архитектура физики и захвата (после миграции в Сессии 5)

**Физика мира.** Атрибут `physx` на `<a-scene>` с параметрами:
- `autoLoad: true` — система сама грузит wasm и стартует симуляцию.
- `delay: 1000` — пауза перед стартом (ждём загрузку wasm).
- `useDefaultScene: false` — пол и стены делаем свои (точное совпадение визуала и физики).
- `gravity: 0 -9.8 0`.
- `wasmUrl: https://cdn.jsdelivr.net/.../physx.release.wasm` — обязательно явный URL, иначе 404.

**Статические тела.** Пол, потолок, 4 стены, пьедестал — `physx-body="type: static"` + `physx-material="restitution: 0.95; staticFriction: 0.05; dynamicFriction: 0.05"` (минимальное трение и высокая упругость нужны плавающим кубикам, см. ниже).

**Динамические тела.** Кубики и другие интерактивные объекты — `physx-body="type: dynamic; mass: <число>"`.

**Руки.** Entity с `hand-controls` + `gltf-model` + `physx-grab`. Внутри — дочерний невидимый коллайдер `<a-sphere physx-body="type: kinematic; emitCollisionEvents: true">`. Радиус 0.05 — баланс между точностью попадания и ложными захватами. `hand-controls` и `physx-grab` уживаются на одном entity без конфликтов (риск из Сессии 5 снят).

**Захват.** Компонент `physx-grab` (локальная копия из `examples/components/grab.js`):
1. На `gripdown`/`triggerdown` — флаг `grabbing = true`.
2. На `contactbegin` (если флаг стоит) — создаётся `physx-joint type: Fixed` между рукой и телом.
3. На `gripup`/`triggerup` — joint удаляется, тело остаётся dynamic и падает по физике.
Dynamic-объекты в момент захвата остаются dynamic — это позволяет ставить кубик на кубик и реалистично кидать.

**Производительность.** В песочнице tick-time PhysX держится 0.10–0.20 ms на сцене с одним dynamic-телом. С 11 dynamic-кубиками + постоянным `wakeUp()` каждый кадр (Сессия 7) ощутимой просадки в Quest 3 не наблюдается — запас остаётся.

### Работа с PhysX-WASM API напрямую (после Сессии 6, уточнено в Сессии 7)

Когда из своих компонентов нужно дёргать PhysX-API напрямую (флаги, скорости, позы), действуют правила:

1. **Доступ к PhysX-биндингу — только через систему сцены:** `sceneEl.systems.physx.PhysX`. Глобального `PhysX` или `window.PhysX` нет.
2. **Энумы PhysX (`PxActorFlag`, `PxShapeFlag`, и т.п.) — это объекты-обёртки с полем `.value`, не числа.** В методы биндинга (`setActorFlag`, `setShapeFlag`, …) нужно передавать сам объект-обёртку, например `PX.PxActorFlag.eDISABLE_GRAVITY`. Передача числа (например, `setActorFlag(2, true)`) **молча игнорируется**, исключения не выбрасываются — тело продолжает работать с дефолтным поведением.
3. **Готовность `rigidBody` ловится поллингом** `el.components['physx-body'].rigidBody` каждые ~100 мс. События `body-loaded` / `physx-body-loaded` в этой версии не приходят стабильно — оставляем как страховку, основной путь — поллинг.
4. **Векторы передаются как plain JS-объекты `{x, y, z}`.** В биндинге `@c-frame/physx@0.3.0` **класса `PxVec3` нет** (есть только контейнер-массив `PxVec3Vector`). Проверено перебором четырёх API в Сессии 6: `new PX.PxVec3(...)` падает, plain object работает, `THREE.Vector3` работает (избыточно), отдельные аргументы `(x, y, z, autowake)` не поддерживаются. Ручной `delete()` для plain-объектов не нужен.
5. **Сон тел.** `setSleepThreshold(0)` сам по себе **не гарантирует**, что dynamic-тело не уснёт. Для float-объектов (без гравитации, низкие скорости) обязательно дополнительно вызывать `wakeUp()` каждый кадр в `tick`, если `isSleeping()`. Иначе через несколько секунд тело замирает.
6. **Потери энергии в контакте — особенность биндинга.** Лечить материалами (restitution=1.0 на обоих контактах) и нулевым damping недостаточно — амплитуда всё равно падает. Рабочее решение — компенсация начальными условиями: повышенная стартовая скорость + угловое вращение + restitution стен **выше**, чем у динамики.

Используется в `js/components/floating-cube.js` (отключение гравитации, damping, sleep-контроль, стартовые линейный и угловой импульсы).

## 🐛 ИЗВЕСТНЫЕ ПРОБЛЕМЫ

### VR-руки иногда не отображаются без VPN

Симптом: `hand-controls` не показывает дефолтную модель руки. Решение — локальные GLB в `assets/models/leftHandLow.glb` и `rightHandLow.glb`, подключаются через `gltf-model`. Сейчас работает стабильно.

После миграции на PhysX (Сессия 5) проблема не изменилась — она про модель руки, не про физику.

### Сторонний `extensionPageScript.js` в Network

Виден в DevTools → Network. Это инжект от браузерного расширения (наблюдалось при включённом AdBlock Plus). К проекту отношения не имеет, на работу не влияет. Игнорировать.

### Гонка инициализации float-кубиков

Между парсингом DOM и готовностью `rigidBody` (~100–200 мс) кубик находится под дефолтной гравитацией и успевает сместиться вниз на десяток сантиметров. Принято: жить с этим до Этапа 4 (замедление времени) или до централизованного спавнера. На геймплей не влияет.

## Сессия 8 — Купол: физика и прозрачность для руки

**Этап:** 3 — Купол над столом
**Статус задачи 3 после сессии:** Шаги 1, 2, 3 закрыты с оговоркой
(см. ниже). Шаги 4, 5, 6 — не начаты. Перед Шагом 4 вклинивается новый
**Шаг 3.5 — система collision groups** (см. CURRENT_TASK.md).

### Что сделано

#### Шаг 1 — Визуальный купол ✅
- В `js/config.js` добавлен раздел `CONFIG.dome` (radius 0.27,
  cylinderHeight 0.30, centerY 1.15, материал, параметры gravityMode для
  будущего Шага 4).
- В `index.html` появились два визуальных entity без физики:
  `a-cylinder` (open-ended, Y=1.00…1.30) и `a-sphere` (theta-length 90°,
  центр Y=1.30). Полупрозрачные, голубые. Рука и кубики проходят насквозь —
  как и задумано на этом шаге.

#### Шаг 2 — Физика купола ⚠️ отклонение от плана
План: два static-тела PhysX (`a-cylinder` open-ended + `a-sphere`
theta-length) с `physx-body="type: static"`.

**Не сработало.** PhysX/A-Frame на open-ended цилиндре и полусфере не
строит точный shape: стенки оказывались дырявыми / не той формы, кубики
прошивали их насквозь.

**Реальное решение:** купол собран из **89 мелких static-плиток** (кубиков),
аппроксимирующих цилиндрическую стенку и полусферическую крышку. Каждая
плитка — отдельный entity с `physx-body="type: static"`. Геометрически
плотно, без щелей. На FPS в Quest не повлияло (89 static-коллайдеров —
дёшево). Визуальные `a-cylinder` и `a-sphere` оставлены как есть —
показывают форму, но физики не несут.

#### Шаг 3 — Прозрачность купола во время grab ⚠️ принято временное решение
План: глобальный режим — пока есть активный grab, у всех 89 плиток купола
снимается `eSIMULATION_SHAPE`; новый компонент `dome-permeable.js`.

**Реализовано иначе.** Изменён только `js/components/physx-grab.js`. В
момент захвата у **самого схваченного кубика** на всех его shape'ах
снимается флаг `eSIMULATION_SHAPE` — кубик становится фантомом. Joint
типа Fixed удерживает его у руки независимо от коллизий. В момент release
флаг возвращается. Файл `dome-permeable.js` **не создавался**.

**Проблема, обнаруженная по ходу теста (см. ниже):** `eSIMULATION_SHAPE`
выключает коллизии **полностью**, а не «только с куполом». Поэтому
схваченный кубик проходит сквозь стол, пол, **и сквозь другие кубики**.
Игрок не может использовать кубик-в-руке как биту — отбивать им другие
кубики и (в будущем) красные шары. Это противоречит задуманной механике.

#### Шаг 3 пересмотрен → Шаг 3.5 поставлен в план
Решено реализовать **точечную фильтрацию коллизий через группы**
(PxFilterData / collision groups), а не грубую фантомизацию shape'ом.
Подробности — в CURRENT_TASK.md, раздел «Архитектурные решения, ревизия
после Сессии 8» и «Шаг 3.5».

Текущий код Шага 3 (фантомизация всего кубика) **остаётся работать как
промежуточное решение** до тех пор, пока в Сессии 9 не будет реализован
Шаг 3.5. То есть купол прозрачен для руки уже сейчас, но Шаг 3.5 заменит
механизм на правильный.

### Открытия по API c-frame/physx@v0.3.0

Через диагностический лог в `addJoint`/`removeJoint` выяснено:
- Shape'ы рaйди-тела лежат в **`el.components['physx-body'].shapes`** —
  массив объектов `PxShape`. У `rigidBody` (`PxRigidDynamic`) метода
  `getShapes()` в этой обёртке **нет**.
- Флаг доступен как
  **`sceneEl.systems.physx.PhysX.PxShapeFlag.eSIMULATION_SHAPE`**.
- Переключается через **`shape.setFlag(flag, boolean)`** — работает «на
  лету», без пересоздания тела.

Эти знания пригодятся для Шага 3.5 (нужно ещё разобраться с
`setSimulationFilterData` и фильтр-шейдером обёртки) и в задачах, где
нужна точечная фантомизация (например, красные шары на Этапе 6).

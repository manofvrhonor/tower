## 🎯 ГЛАВНАЯ ЦЕЛЬ

VR-игра **Tower of Time** для Meta Quest 3 в браузере (WebXR), по постоянной ссылке.

### Геймплей

Игрок в белой комнате 3×3×3 м. В центре — стол-пьедестал с прозрачным куполом. Вокруг в невесомости плавают:
- **цветные кубики** — для сборки башни по схеме на столе;
- **серые мусорные кубики** — визуальный шум (`isTarget: false`);
- **красные светящиеся шары с трейлами** — летают по траекториям, опасны.

### Купол

- Плавающие кубики отскакивают от купола снаружи.
- Рука с кубиком свободно проходит сквозь.
- Отпустил кубик внутри → становится физическим, падает на стол.
- Отпустил снаружи → летит в невесомости с импульсом руки.
- Скатился со стола, коснулся пола → возвращается в плавающий режим.
- Красные шары проходят сквозь купол, могут сбить башню.

### Замедление времени (как в игре SUPERHOT)

- Игрок замер → `timeScale ≈ 0.05`.
- Двигается → `timeScale = 1.0`.
- Применяется к скриптовому движению (плавающие кубики, шары).
- Физика рук, физика на столе, сам игрок — реальное время.

### Отбивание

В комнате — бита/сковородка/ракетка/рыба, ими отбиваются красные шары.

### Победа / поражение

- **Победа:** башня собрана по схеме, неподвижна несколько секунд.
- **Поражение:** красный шар коснулся капсулы тела игрока.

### MVP

Друг надевает шлем без объяснений, проходит за 2–5 минут, говорит «прикольно».

### Таймлайн

~1 неделя.

### Не-цели

Уровни, меню, сохранения, графика AAA, мультиплеер, не-VR версии.

## 🏗 АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### CDN — только jsDelivr

Все внешние библиотеки — через `https://cdn.jsdelivr.net/`.
Не использовать: `aframe.io`, `unpkg.com`, `cdn.aframe.io`, любые другие CDN.
Причина: стабильность из РФ без VPN, единая точка отказа.

### Стратегия тестирования — локально, не Netlify

- Цикл разработки: правка → сохранить → `npx serve` → перезагрузить вкладку Chrome → при необходимости войти в VR через Quest Link.
- **Quest Link + localhost.** Quest 3 подключён к ПК через Quest Link. В десктопном Chrome на `http://localhost:<порт>` иммерсивный VR работает напрямую — шлем показывает то, что в браузере.
- Деплой Netlify — только в конце этапа или по явному запросу пользователя.
- Публичная HTTPS-ссылка нужна, только если тестируем в Quest Browser напрямую (без Quest Link). Тогда — деплой по запросу.

### Git и откаты

- Каждый микро-шаг = отдельный коммит в `main`.
- Откаты — через `git reset` / `git checkout`, не через Netlify rollback.
- `git push` — пакетом в конце сессии или для бэкапа, не после каждого коммита.

### Архитектура физики и захвата (после миграции в Сессии 5)

**Физика мира.** Атрибут `physx` на `<a-scene>` с параметрами:
- `autoLoad: true` — система сама грузит wasm и стартует симуляцию.
- `delay: 1000` — пауза перед стартом (ждём загрузку wasm).
- `useDefaultScene: false` — пол и стены делаем свои (точное совпадение визуала и физики).
- `gravity: 0 -9.8 0`.
- `wasmUrl: https://cdn.jsdelivr.net/.../physx.release.wasm` — обязательно явный URL, иначе 404.

**Статические тела.** Пол, потолок, 4 стены, пьедестал — `physx-body="type: static"`. Стены теперь физические, кубики не вылетают из комнаты.

**Динамические тела.** Кубики и другие интерактивные объекты — `physx-body="type: dynamic; mass: <число>"`.

**Руки.** Entity с `hand-controls` + `gltf-model` + `physx-grab`. Внутри — дочерний невидимый коллайдер `<a-sphere physx-body="type: kinematic; emitCollisionEvents: true">`. Радиус 0.05 — баланс между точностью попадания и ложными захватами. `hand-controls` и `physx-grab` уживаются на одном entity без конфликтов (риск из Сессии 5 снят).

**Захват.** Компонент `physx-grab` (локальная копия из `examples/components/grab.js`):
1. На `gripdown`/`triggerdown` — флаг `grabbing = true`.
2. На `contactbegin` (если флаг стоит) — создаётся `physx-joint type: Fixed` между рукой и телом.
3. На `gripup`/`triggerup` — joint удаляется, тело остаётся dynamic и падает по физике.
Dynamic-объекты в момент захвата остаются dynamic — это позволяет ставить кубик на кубик и реалистично кидать.

**Производительность.** В песочнице tick-time PhysX держится 0.10–0.20 ms на сцене с одним dynamic-телом. Запас на сложную сцену большой.

### Работа с PhysX-WASM API напрямую (после Сессии 6)

Когда из своих компонентов нужно дёргать PhysX-API напрямую (флаги, скорости, позы), действуют правила:

1. **Доступ к PhysX-биндингу — только через систему сцены:** `sceneEl.systems.physx.PhysX`. Глобального `PhysX` или `window.PhysX` нет.
2. **Энумы PhysX (`PxActorFlag`, `PxShapeFlag`, и т.п.) — это объекты-обёртки с полем `.value`, не числа.** В методы биндинга (`setActorFlag`, `setShapeFlag`, …) нужно передавать сам объект-обёртку, например `PX.PxActorFlag.eDISABLE_GRAVITY`. Передача числа (например, `setActorFlag(2, true)`) **молча игнорируется**, исключения не выбрасываются — тело продолжает работать с дефолтным поведением.
3. **Готовность `rigidBody` ловится поллингом** `el.components['physx-body'].rigidBody` каждые ~100 мс. События `body-loaded` / `physx-body-loaded` в этой версии не приходят стабильно — оставляем как страховку, основной путь — поллинг.
4. **Векторы передаются как plain JS-объекты `{x, y, z}`**, не через конструктор. В биндинге @c-frame/physx@0.3.0 **класса `PxVec3` нет** (есть только `PxVec3Vector` — контейнер-массив, не сам тип). Проверено перебором четырёх API в Сессии 6. Соответственно, ручной `delete()` для векторов не требуется.

Используется в `js/components/floating-cube.js` (отключение гравитации, damping, обнуление скорости).

- **Шаг 4 закрыт в этой же сессии (после паузы):** добавлен стартовый импульс случайного направления через `rb.setLinearVelocity({x, y, z}, true)`. До рабочего варианта дошли диагностическим перебором четырёх API: `new PX.PxVec3(...)` (упало — класса нет в биндинге), plain object (сработало), `THREE.Vector3` (сработало бы, но избыточно), отдельные аргументы `(x, y, z, autowake)` (не поддерживается). **Уточнение к разделу «Работа с PhysX-WASM API напрямую»: пункт 4 про `PxVec3` неверен для @c-frame/physx@0.3.0 — класса `PxVec3` в биндинге нет, векторы передаются как `{x, y, z}`, `delete()` не нужен.**
- Обсуждалась локализация внешних библиотек (vendor'инг A-Frame и PhysX в `vendor/`). Решено **не делать** — не критично, оставляем CDN jsDelivr.

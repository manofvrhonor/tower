## 🎯 ГЛАВНАЯ ЦЕЛЬ

VR-игра **Tower of Time** для Meta Quest 3 в браузере (WebXR), запускаемая по постоянной ссылке.

**Геймплей:** Игрок в небольшой белой комнате. Посередине стол с прозрачным куполом-колбой. Вокруг в невесомости плавают:
- **Цветные кубики** — нужны для сборки башни по схеме на столе
- **Серые мусорные кубики** — ведут себя как цветные, создают визуальный шум (`isTarget: false`)
- **Красные светящиеся шары с трейлами** — летают по траекториям, опасны

**Механика купола:**
- Плавающие кубики **отскакивают** от купола снаружи
- **Рука игрока с кубиком** свободно проходит сквозь купол
- Если отпустить кубик **внутри** купола → становится физическим, падает на стол
- Если отпустить **снаружи** купола → продолжает летать в невесомости с импульсом от руки
- Если физический кубик скатился со стола и коснулся пола → возвращается в плавающий режим
- **Красные шары** проходят сквозь купол — могут сбить собранную башню

**Замедление времени (ядро как механика в игре SUPERHOT):** Игрок замер → время почти стоит (`timeScale ≈ 0.05`). Игрок двигается → нормальное время (`timeScale = 1.0`). Применяется к скриптовому движению (плавающие кубики, красные шары). Физика рук, физика на столе и сам игрок — всегда реальное время.

**Отбивание:** в комнате есть разные предметы - бита, или сковородка, или ракетка, или рыба, ими можно отбивать красные шары.

**Победа:** собрана башня по схеме (правильные цвета в правильных позициях, неподвижно несколько секунд).
**Поражение:** красный шар коснулся капсулы тела игрока.

**Критерий успеха MVP:** друг надевает шлем, открывает ссылку, без объяснений понимает что делать, проходит за 2–5 минут, говорит «о, прикольно».

**Таймлайн MVP:** ~1 неделя активной работы.

**Не-цели:** несколько уровней, меню/настройки/сохранения, богатая графика, мультиплеер, мобильная/десктоп-версия.

## 🛠️ ТЕХНОЛОГИЧЕСКИЙ СТЕК (ЗАФИКСИРОВАН — НЕ МЕНЯЕТСЯ)

### Основа
- **A-Frame 1.5.0** (через CDN: `https://cdn.jsdelivr.net/npm/aframe@1.5.0/dist/aframe-master.min.js`)
- **Three.js** — внутри A-Frame (r158), отдельно не подключаем
- **WebXR API** — обёрнут A-Frame

### Компоненты A-Frame
- **`@c-frame/physx`** (PhysX от NVIDIA, скомпилирован в WASM) — единый физический движок для всей сцены: пол, пьедестал, плавающие кубики, физическая башня, бита, купол, захват руками. **В комплекте идут компоненты `physx-grabbable` и `hand-grab`**, которые обрабатывают захват/бросок по триггеру контроллера с правильным импульсом — отдельный пакет для grab не нужен. Подключим на шаге 1.3 (Сессия 5). Точная версия и CDN-ссылка определяются в начале Сессии 5.
- **`hand-controls`** (встроенный компонент A-Frame) — отображение и трекинг рук Quest 3. Подключён на шаге 1.2. С локальными GLB-моделями `assets/models/leftHandLow.glb` и `rightHandLow.glb` (см. «Архитектурные решения»). На шаге 1.3 на entity рук добавится `physx-body="type: kinematic"` + `hand-grab` (возможно, в связке с `oculus-touch-controls` или `meta-touch-controls` — уточняется в Сессии 5).
- ~~**`@c-frame/aframe-physics-system` 4.2.2**~~ (Cannon.js) — **отключается в Сессии 5.** Заменяется на `@c-frame/physx` (см. архитектурное решение «Разворот с Cannon на PhysX»).
- ~~**super-hands**~~ — **отказались в Сессии 5, не подключали.** Захват реализуется встроенными компонентами `@c-frame/physx`.
- **aframe-extras** — опциональные утилиты *(по мере надобности)*

### Подход к коду
- **Без сборщиков** (нет Webpack, нет Vite, нет npm install для библиотек)
- Чистый **HTML + ES-модули JavaScript**
- **Без TypeScript**
- Все библиотеки — через `<script src="https://cdn..."></script>` в `index.html`
- Один компонент A-Frame = один файл в `js/components/`
- Все геймплейные числа — в `js/config.js`
- **Git как единственный источник версий:** каждый микро-шаг = коммит в `main`. Откаты делаем через `git`, не через Netlify rollback. `git push` на GitHub — в конце сессии или по необходимости (для бэкапа в облако).

### Чего НЕ используем (категорически)
- ❌ Vite, Webpack, Parcel, Rollup
- ❌ TypeScript
- ❌ React, Vue, Svelte
- ❌ npm-зависимости проекта (всё через CDN)
- ❌ Unity, Godot, Unreal
- ❌ Готовые 3D-модели на старте (только примитивы A-Frame)

## 🏛️ АРХИТЕКТУРНЫЕ РЕШЕНИЯ

> Сюда заносим решения, которые влияют на весь проект и которые легко забыть. Формат: **что решили / почему / какие последствия**.

### Размер комнаты — куб 3×3×3 метра
- **Что:** игровая комната — куб 3×3×3 м.
- **Почему:** Quest 3 guardian не должен выходить за границы доступной комнаты в реальности. 3×3 м — зона, в которой игрок физически может перемещаться без риска удариться о настоящие стены.
- **Последствия:** все игровые объекты (пьедестал, башня, плавающие кубики, инструменты для отбивания) должны умещаться в этом объёме. Стартовая позиция игрока — `(0, 0, 1)` (1 м южнее пьедестала, лицом к нему).
- **Подтверждено:** на Этапе 0 проверено в Quest 3 — игрок физически вошёл в иммерсивный VR, прошёлся по комнате, масштабы 3×3 м соответствуют реальной свободной зоне, дискомфорта нет.

### Стол-пьедестал вместо обычного стола
- **Что:** «стол» в центре комнаты — это вертикальный цилиндр (радиус 0.3 м, высота 1 м), как пьедестал в музее.
- **Почему:** компактнее обычного стола (важно в комнате 3×3 м), визуально центрирует внимание на объекте сверху, эстетика «выставочный экспонат».
- **Последствия:** на Этапе 1 хватание и физика будут работать с верхней круглой плоскостью пьедестала диаметром 60 см — этого достаточно для башни из ~5 кубиков по 5 см.
- **Подтверждено:** на Этапе 0 проверено в Quest 3 — высота и положение пьедестала ощущаются естественно.

### CDN — только jsDelivr, не aframe.io / unpkg
- **Что:** все внешние библиотеки (A-Frame и будущие компоненты) подключаются через `https://cdn.jsdelivr.net/`, а не через `aframe.io`, `unpkg.com` или другие CDN.
- **Почему:** разработчик находится в РФ. Сайт `aframe.io` имеет нестабильный доступ из РФ — сцена может не загружаться без VPN. То же касается `unpkg.com`. jsDelivr стабильно работает из любой страны без VPN, что критично для:
  - локальной разработки без VPN-зависимости;
  - тестирования в Quest 3 (у браузера в шлеме отдельный кеш и нет своего VPN);
  - друзей-тестировщиков, которые откроют публичную ссылку.
- **Последствия:** при добавлении любой новой библиотеки берём ссылку с `cdn.jsdelivr.net/npm/<пакет>` или `cdn.jsdelivr.net/gh/<репозиторий>`. Никаких других CDN.

### Netlify — деплой статики без билда
- **Что:** настройки Netlify: **Build command — пусто**, **Publish directory — корень репозитория** (`.`). Никаких `npm run build`, `npm install`, `dist/`.
- **Почему:** проект чистый HTML + JS + CDN-библиотеки, никакой сборки не требуется. `index.html` готов к раздаче как есть. На старте Netlify по инерции от Vite-проекта пытался запускать `npm run build`, что приводило к Failed-деплоям после удаления `package.json`.
- **Последствия:** деплой проходит за ~4 секунды (просто копирование файлов). При добавлении любого инструмента, требующего сборки (что не планируется), эти настройки придётся менять.

### Физика — форк `@c-frame/aframe-physics-system`, не оригинал
- **Что:** в Сессиях 2–4 для физики использовался форк `@c-frame/aframe-physics-system@4.2.2` (Cannon.js).
- **Почему:** оригинальный пакет `aframe-physics-system` (последний релиз 4.0.2, 2021 год) заброшен мейнтейнером и несовместим с современным A-Frame. При попытке использовать его с A-Frame 1.5.0 (Three.js r158) валится с ошибкой `Uncaught TypeError: t.Geometry is not a constructor` — пакет вызывает `THREE.Geometry`, который удалён из Three.js начиная с r125. Тела не создаются, физика не работает. Организация **c-frame** взяла на себя поддержку экосистемы A-Frame после того, как оригиналы были заброшены.
- **Подтверждено:** на шаге 1.1 проверено локально — кубик с `dynamic-body` корректно падал на пол со `static-body`.
- **⚠️ ОТМЕНЕНО В СЕССИИ 5:** Cannon-стек заменён на `@c-frame/physx` (см. блок «Разворот с Cannon на PhysX» ниже). Этот раздел оставлен для истории — чтобы понимать, почему мы вообще были на c-frame форке и почему остаёмся в той же экосистеме.

### VR-руки — `hand-controls` + локальные GLB-модели
- **Что:** для отображения рук в VR используется встроенный компонент A-Frame `hand-controls` (а не super-hands), с подгрузкой собственных GLB-моделей из `assets/models/leftHandLow.glb` и `rightHandLow.glb` через атрибут `gltf-model`. Оба entity рук находятся **внутри** rig'а игрока `<a-entity id="player">`, рядом с `<a-camera>`.
- **Почему встроенный `hand-controls`:** на шаге 1.2 нужна была только визуализация и трекинг рук, без хватания. Встроенного компонента для этого достаточно.
- **Почему локальные GLB, а не дефолтные модели:** дефолтные модели `hand-controls` подгружаются с CDN, который без VPN из РФ работает нестабильно. Локальные GLB лежат в репозитории (`assets/models/`) и раздаются с Netlify.
- **Почему руки внутри rig'а игрока:** если объявить entity рук на верхнем уровне `<a-scene>`, они не наследуют трансформацию rig'а — позиционируются в мировых координатах и не следуют за игроком. Поэтому оба `<a-entity>` рук — дети `<a-entity id="player">`.
- **Известная проблема:** даже с локальными моделями руки могут не отображаться без VPN — предположительно `hand-controls` внутри себя обращается к каким-то ресурсам на заблокированном CDN. Не чиним до тех пор, пока это не начнёт ломать игру (договорённость с пользователем).

### Стратегия тестирования — локально через Quest Link, Netlify редко
- **Что:** в течение работы над микро-шагом тестирование идёт **локально** — `npx serve` на ПК, Meta Quest 3 подключён через Quest Link, в десктопном Chrome открывается `http://localhost:3000` (или порт, который выдаст `serve`). Деплой на Netlify делаем **только** в конце этапа из дорожной карты или для контрольной проверки публичной ссылки, после одобрения пользователем.
- **Почему:** деплои на Netlify платные.
- **Последствия:**
  - Сохранение версий теперь полностью на стороне Git/GitHub, а не «текущее на Netlify».
  - Откаты делаем через `git`, не через Netlify rollback.
  - Каждый микро-шаг = отдельный коммит в `main`, но `git push` на GitHub можно делать пакетом в конце сессии — это не запускает Netlify-деплой автоматически.
  - Авто-деплой Netlify ← `main` отключён. Деплой запускается **вручную** через Netlify UI (Trigger deploy).
- **Подтверждено:** локальный запуск `npx serve` + Quest Link + иммерсивный VR в десктопном Chrome проверен пользователем, сцена открывается и работает.

### Разворот с `@c-frame/aframe-physics-system` (Cannon) на `@c-frame/physx` (PhysX) + отказ от super-hands
- **Что:** в Сессии 5 связка «Cannon-физика + super-hands для захвата» заменена на единый стек `@c-frame/physx`. PhysX выполняет роль и физического движка, и системы захвата — у пакета в комплекте идут компоненты `physx-grabbable` (на захватываемые объекты) и `hand-grab` (на entity руки). Cannon-физика и super-hands из проекта удаляются.
- **Почему:**
  1. В Сессии 4 потрачен полный заход на отладку super-hands. Компонент не регистрируется в `AFRAME.components`, бандл прерывается между регистрацией `grabbable` и `stretchable`. Первопричина не найдена — есть гипотеза о конфликте с расширениями браузера, но не подтверждена. Дальнейшая отладка — это вложение времени в починку **заброшенного** стека ради сомнительной выгоды.
  2. Cannon-стек известен проблемами с захватом и бросками: рывки, неправильные импульсы при release, дрожание стопок объектов. Для Tower of Time это критично — нам нужны и стопка из ~5 кубиков (башня), и точный импульс при отбивании красных шаров битой, и корректный импульс при отпускании плавающего кубика снаружи купола.
  3. PhysX — современный, активно поддерживаемый движок. Стопки объектов держатся стабильнее, импульсы при бросках корректны. Захват встроен, поэтому отдельной библиотеки уровня super-hands не требуется.
  4. Мы остаёмся внутри той же экосистемы — организация **c-frame** уже зарекомендовала себя как поддерживающая форки A-Frame-компонентов.
- **Последствия:**
  - Из `index.html` удаляются подключения `@c-frame/aframe-physics-system@4.2.2` и `super-hands.min.js`.
  - На пол и пьедестал атрибут `static-body` заменяется на `physx-body="type: static"`.
  - На тестовом кубике `dynamic-body="mass: 1"` заменяется на `physx-body="type: dynamic; mass: 1"` + добавляется `physx-grabbable`.
  - На entity рук добавляется `physx-body="type: kinematic"` + `hand-grab`.
  - PhysX тянет `.wasm`-файл при инициализации. Если CDN с `.wasm` недоступен из РФ — `.wasm` кладётся локально в `assets/`. Решается в Сессии 5 при первом запуске.
  - Отдельный пакет `sphere-collider` больше не нужен — у PhysX своя система коллизий.
- **Подтверждено:** будет подтверждено в Сессии 5 после прототипирования в `sandbox-physx.html` и миграции основной сцены.
